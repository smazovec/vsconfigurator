## Требуемый результат и граница

Требуется одна визуальная секция: реальное имя конфигурации → отдельная строка пиктограмм → постоянное поле «Имя или синоним…» → существующий native TreeView. Отдельные секции поиска, дерева, фильтров и помощи исключены. Замена дерева HTML-реализацией запрещена.

Текущая реализация PR этому критерию **не соответствует**: поиск и дерево являются разными views. Изменение `name`, размера или порядка views не устраняет этот дефект. Ниже зафиксирована проверенная граница API; косметический вариант не объявляется исправлением.

## Проверенные механизмы

| Требование | Применимость в обычном расширении VS Code 1.125.0 |
| --- | --- |
| Менять заголовок существующего дерева | Публичное `TreeView.title` позволяет динамически менять название самого view. Имя конфигурации нужно читать из её метаданных. Это не публичный setter заголовка всего контейнера: `viewsContainers.title` задаётся манифестом, а объединением заголовков управляет workbench. |
| Получить настоящее имя конфигурации | Уже существует чтение `cf-configuration-properties-get` через md-sparrow; `SourcePropertiesDto` содержит `name` и `synonym`. Название папки проекта и подпись «Основная конфигурация» не заменяют эти данные. При реализации потребуются сброс при смене проекта и защита от позднего ответа прежней конфигурации. |
| Пиктограммы команд | `view/title` даёт штатные действия в заголовке, `view/item/context` — у узла. Для отдельной строки под заголовком нужен HTML-view; в `TreeViewOptions` нет слота для такой панели. |
| Постоянный поиск перед узлами TreeView | В полном интерфейсе `TreeView` нет поля ввода, HTML-шапки, произвольного дочернего UI или слота для `Webview`. `message` — строка, а не HTML. `InputBox`/`showInputBox` являются отдельным Quick Input, а не встроенным полем дерева. |
| Спрятать заголовки двух соседних views | В contribution-схеме нет `hideHeader`/`headerVisible`. `visibility` управляет всем view, `initialSize` — его размером. В `ViewPaneContainer.updateViewHeaders` заголовки нескольких views явно включаются; объединение с контейнером применяется только при одном view. Скрытый поиск скрывает и поле. |
| Вложить существующий native TreeView в Webview | Публичного механизма нет. Webview управляет своим HTML, а native TreeView создаётся workbench отдельно. HTML-дерево с прежним провайдером всё равно заменило бы native renderer и нарушило прямое ограничение. |
| Убрать отдельные блоки фильтров и помощи | Можно убрать их contributions из основного контейнера и открывать функции командами. Выбор подсистем можно перенести в отдельный `WebviewPanel`, сохранив состояние и вычисление отбора. Это не решает встраивание постоянного поиска в native TreeView. |

Первичные источники Microsoft, зафиксированные на версии 1.125.0:

- [Полный публичный контракт vscode.d.ts](https://github.com/microsoft/vscode/blob/1.125.0/src/vscode-dts/vscode.d.ts): `TreeView`, `TreeViewOptions`, `InputBox`.
- [Схема contributions и регистрация native/webview views](https://github.com/microsoft/vscode/blob/1.125.0/src/vs/workbench/api/browser/viewsExtensionPoint.ts): `viewDescriptor`, `IUserFriendlyViewDescriptor`, `registerCustomViewContainer`, `addViews`.
- [Условия показа заголовков и объединения единственного view](https://github.com/microsoft/vscode/blob/1.125.0/src/vs/workbench/browser/parts/views/viewPaneContainer.ts#L1075-L1117); [вычисление заголовка контейнера](https://github.com/microsoft/vscode/blob/1.125.0/src/vs/workbench/browser/parts/views/viewPaneContainer.ts#L544-L562).
- [Публичные WebviewView и WebviewPanel](https://github.com/microsoft/vscode/blob/1.125.0/src/vscode-dts/vscode.d.ts) и [разделение webview и UI редактора](https://code.visualstudio.com/api/extension-guides/webview).

Координаты существующего механизма чтения свойств: `registerMetadataFeature.ts`, функция `loadSourcePropertiesDto`; контракт — `metadataSourcePropertiesPanel.ts`, `SourcePropertiesDto`. Для проверки использованы исходники, а не предположение по внешнему виду изображения.

## Вывод

Точная геометрия изображения не реализуется доступным публичным API обычного расширения при одновременном сохранении native TreeView. Блокируют именно постоянное поле и отдельная панель внутри единого view. Динамический заголовок и перенос фильтров реализуемы отдельно, но их выполнение не означает достижения всего критерия.

Непубличный доступ к DOM workbench, CSS-инъекции, патч установленного VS Code, proposed API и замена дерева здесь не применены. Существующие файлы реализации и renderer дерева сохранены.

## Варианты для решения Сергея

| Вариант | Что сохраняется | Какое требование нужно изменить |
| --- | --- | --- |
| **A. Один native TreeView** | Существующее дерево, его выделение, иконки и команды; динамический заголовок view; фильтры вне основного контейнера | Пиктограммы находятся в штатном заголовке, поиск открывается отдельным InputBox и вызывает прежний `setTextFilter`. Постоянного поля и отдельного ряда кнопок под заголовком нет. Верхний заголовок контейнера формирует workbench. |
| **B. Постоянный поиск с native TreeView** | Существующее дерево и постоянные пиктограммы/поле перед ним; фильтры вне основного контейнера | Нужно явно разрешить два соседних view с их штатными заголовками. Это ограничение уже отвергнутой компоновки; вариант приведён только как явный выбор компромисса, а не предлагается как выполненный критерий. |
| **C. Точное изображение с native TreeView** | Целевая геометрия и штатное дерево | Нужна отдельная задача на изменение workbench/API редактора и собственную сборку/форк VS Code либо появление поддерживаемого upstream API. В текущем расширении и текущем PR это не доступная правка. |

Выбор не сделан автоматически. Замена native TreeView HTML-деревом не входит ни в один вариант.
