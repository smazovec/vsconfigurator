# Приёмка навигатора метаданных — Issue #5

Основание: [bounded task, comment 6539036004](https://github.com/smazovec/vsconfigurator/issues/5#issuecomment-6539036004).
Исполнитель: Codex. Предметный владелец: Мастер (`atlas`). Решение и запуск: Сергей.
База: `424238426243565bafe96f9e7611e18feeadfd4e`, `main`.

## Результат и область

Существующий `MetadataTreeDataProvider` и VS Code TreeView сохранены. Над деревом — раскрытый поиск с панелью пиктограмм; список подсистем по умолчанию свёрнут под деревом. Панель передаёт существующим командам конкретный узел, проверяет доступность повторно при клике и отклоняет сообщение от прежнего выделения. После перестроения дерева требуется снова выбрать узел.

Поиск по имени, синониму и нескольким словам, раскрытие результатов, множественный отбор и опции родительских/дочерних подсистем используют прежние механизмы. Очистка отбора теперь сразу снимает и отбор, и отметки, отменяя отложенное применение. Настройка `1c-platform-tools.metadata.autoOpen` по умолчанию включает одну попытку открытия при первом обнаружении проекта в окне.

Дополнительные относительно исходного списка файлы понадобились для маршрутизации панели (`metadataToolbar.ts`), объединения очистки с существующей командой (`registerMetadataFeature.ts`), соразмерных тестов, воспроизводимого smoke-сценария и этой инструкции. В тесте заголовков учтён перенос настроек метаданных в меню проекта. Новых операций записи, XML-изменений, обработчиков вместо существующих или изменений `md-sparrow` нет.

## Компромиссы VS Code

- Поле и панель находятся в отдельном webview-view **Поиск**: штатный TreeView не поддерживает HTML/поле ввода в своём заголовке. Заголовки и разделитель двух views остаются.
- Размеры, порядок и скрытие views сохраняет сам VS Code. Умолчания применяются к новой компоновке; вручную изменённую компоновку расширение не сбрасывает.
- При старте используется автокоманда `<viewId>.focus` от contributed view. У `TreeView.reveal` требуется уже существующий узел; публичного `TreeView.show` нет. Проверка наличия focus-команд включена в тесты VS Code 1.125.0; отдельный smoke-сценарий проверяет их реальный вызов после активации расширения. На других версиях и форках полный результат не гарантирован.
- Пиктограммы переносятся на следующую строку. При уменьшении высоты view потребуется увеличить его штатным разделителем. Контекстные меню остаются альтернативным доступом к действиям.
- Автотесты проверяют маршрутизацию и признаки запрета записи, но не файловые ACL конкретной конфигурации и не реальную запись через внешние компоненты.

## Ручная проверка Сергеем в обычном VS Code

GUI-приёмка реальной конфигурации в обычном VS Code и визуальная проверка тем здесь не заявляются выполненными. Используйте чистый профиль VS Code 1.125.0+ с собранным VSIX, тестовую копию проекта и настроенными компонентами md-sparrow/JRE.

1. Откройте папку с `packagedef` и метаданными: панель метаданных должна открыться один раз, поиск быть над штатным деревом. Перезапустите окно и повторите. Откройте обычную папку без проекта: стартовый раздел должен остаться прежним.
2. Выключите `1c-platform-tools.metadata.autoOpen`, перезапустите окно с проектом: автоматического перехода быть не должно. Верните настройку, снова перезапустите.
3. Перейдите в Explorer, откройте/сохраните BSL-файл, обновите дерево, смените текущий проект и повторно обнаружьте проекты: навигатор не должен перехватывать фокус. Проверьте доступность Search, Source Control и Terminal.
4. Найдите объект по имени, по синониму и двумя словами; проверьте раскрытие ветвей, пустой результат, крестик и Escape. Закройте и снова откройте раздел: поле должно соответствовать отбору дерева.
5. Откройте воронку, отметьте несколько подсистем, включите/выключите обе опции. Проверьте объединение состава и независимый поиск подсистем. Сверните список: активность отбора остаётся видна. Крестик рядом с воронкой должен убрать и отбор, и отметки. Смена проекта также снимает отбор.
6. На тестовой копии выделите группу справочников, справочник, неподдерживаемый для дублирования вид, раздел реквизитов, реквизит, форму, макет, основную конфигурацию и расширение. Проверьте доступность и точный объект действий добавления/просмотра/дублирования/удаления; отмените удаление, затем отдельно проверьте подтверждённое удаление копии. Проверьте внешний отчёт/обработку и поддерживаемый проект EDT.
7. Проверьте заблокированный поддержкой объект, отдельно разрешённую форму, конфигурацию без разрешения редактирования и режим без записи. Кнопки мутации должны соответствовать запретам, просмотр оставаться доступным. После обновления выберите узел заново. Отмена диалогов не должна менять файлы.
8. Сузьте боковую панель примерно до 180–240 px, проверьте перенос пиктограмм, tooltip и Tab/Enter/Space. Проверьте меню **Ещё**, светлую, тёмную и контрастную темы, отображение отбора и стандартные контекстные меню. Для привычной сохранённой компоновки отдельно проверьте возвращение плашки через меню views.
